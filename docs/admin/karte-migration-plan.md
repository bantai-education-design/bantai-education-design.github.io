# Ban.Tai Education Design — KARTE移行・共存計画書

## 1. 現状と基本方針

本サイトでは、従来KARTE（karte.io）を利用してユーザー行動（`click_action` 等）の計測を行っていました。

今回の改修では以下の方針をとっています：
- **GA4を正本化**: サイト全体のアクセス解析および主要イベント計測の主軸を GA4（`G-KPGJ0R2KXR`）へ統一。
- **KARTEは削除しない**: 既存の配信設定や管理側の過去ログとの整合性を維持するため、KARTEタグおよび `krt('send', ...)` 処理は削除せず併用を継続。

## 2. 現在の共存状態

### 2.1 スクリプト構成
- 各公開HTMLファイルにおいて、GA4の統一スニペットとKARTEタグスニペットが並行して読み込まれています。
- `assets/js/analytics-events.js` では、主要クリック時に KARTE向け `krt('send', 'click_action', { item_name })` と GA4向け `gtag('event', ...)` の双方が発行されます。
- ファイルダウンロードについては、GA4側は拡張計測による自動収集を利用し、KARTE側は既存の `click_action` を送信します。

### 2.2 影響範囲
- 両サービスが独立して動作するため、片方の障害や停止が他方に影響を与えることはありません。
- GA4の本人除外（`bantai_ga_disable`）が有効化された場合も、KARTE側の挙動には影響を与えず安全に分離されています。

## 3. 将来の完全移行（KARTE安全廃止）に向けた手順案

今後、GA4およびLooker Studioによる月次レポート体制が安定し、KARTEの契約終了やタグ廃止を行う場合の標準手順を以下に記録します。

1. **データ並行検証（最低3ヶ月間）**:
   - GA4で計測されたアクティブユーザー数および各イベント数が、想定通りの傾向で取得できているか確認。
2. **KARTEスクリプト呼び出しの整理**:
   - `assets/js/analytics-events.js` 内の `sendKarteEvent` 関数および `krt('send', ...)` の呼び出しを安全に除去。
3. **HTMLからのタグ除去**:
   - 各公開HTMLファイルから KARTE タグ（`<!-- KARTE Tag -->` および `cdn-edge.karte.io`）を除去。
   - 本PRで整備した `tools/audit_html_ga4.py` と同様の検証スクリプトを用意し、公開ページのタグ整合性を自動検査。
