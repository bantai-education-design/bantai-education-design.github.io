# 千葉県学校データ変換計画

更新日: 2026-07-24
参照: [埼玉県版 conversion-guide.md](../saitama/conversion-guide.md) の手順・検証項目を踏襲し、
千葉県特有の差分（単一ファイル構成、幼保連携型認定こども園の収録、地区表示順）を追記する。

本書は調査・設計のみ。`chiba.json` の生成、`tools/school-database/chiba/index.html` の新設、
コミット・push・PR作成は行わない。

---

## 1. 埼玉県版との構造的な違い

| 項目 | 埼玉県版 | 千葉県版 |
| :--- | :--- | :--- |
| 公立データのファイル構成 | 校種ごとに個別Excel（13ファイル） | **単一Excel（`5-1-r7_koritsu_meibo.xls`）に10種の学校シートを収録** |
| 幼保連携型認定こども園 | 対象外 | **対象（`5-1-2(認定こども園)`シート）** |
| 最新反映の方法 | 令和8年度速報版を待って差し替え予定 | **令和7年版を基礎とし、`r8-gakkouichiran-2`の新設・統合・廃止・名称変更一覧で補正** |
| 私立データのファイル形式 | .xlsx（校種別） | .xlsx（校種別、埼玉県と同じ4分類） |
| 表示順 | `MUNICIPALITY_ORDER`配列（行政順） | 同様に配列が必要。ただし原本の「地区」列は教育事務所管轄区分（葛南・東葛飾等）であり、**指定された表示順（千葉市各区→市部→郡部）とは一致しないため、委員会名から独自マッピングを作成する** |

## 2. 実際に確認した原本の構造

### 2-1. 公立学校名簿（`5-1-r7_koritsu_meibo.xls`）

`xlrd`で開いて確認したシート構成（表紙除く10シート）:

| シート名 | 学校種 | 行数 | 備考 |
| :--- | :--- | ---: | :--- |
| 5-1-1(幼稚園) | 幼稚園 | 68 | 国立1園を含む |
| 5-1-2(認定こども園) | 幼保連携型認定こども園 | 46 | |
| 5-1-3(小学校) | 小学校 | 753 | 国立1校を含む |
| 5-1-4(中学校) | 中学校 | 370 | |
| 5-1-5(義務教育学校) | 義務教育学校 | 11 | |
| 5-1-6(中等教育学校) | 中等教育学校 | 9 | |
| 5-1-(7-1)(高等学校(全日制)) | 高等学校・全日制 | 136 | |
| 5-1-(7-2)(高等学校(定時制)) | 高等学校・定時制 | 24 | |
| 5-1-(7-3)(高等学校(通信制)) | 高等学校・通信制 | 9 | |
| 5-1-8(特別支援学校) | 特別支援学校 | 55 | |

各シートは3〜4行のマージされた見出し行の後にデータが始まる。列構成（共通）:

```
A: 委員会名（設置者。国立の場合は "国立"、それ以外は市町村名）
B: 地区（教育事務所管轄区分。表示順の指定には使わない）
C: 区分（多くの行で空欄。分校・分教室フラグの可能性。要個別確認）
D: 学校名／幼稚園名／こども園名
E: 〒（郵便番号）
F: 所在地（"千葉県"の接頭辞なし。例: "千葉市稲毛区弥生町1-33"）
G: ＴＥＬ
H: ＦＡＸ
I以降: 学級数・在園者数・生徒数などの統計列（変換対象外）
```

> [!IMPORTANT]
> 所在地列は都道府県名を含まないため、変換時に必ず先頭へ「千葉県」を付与する
> （[common-data-schema.md](../common-data-schema.md)の「住所は都道府県名から始まる」要件）。

高等学校は全日制・定時制・通信制の3シートに分かれている。埼玉県版と同じ方針で、
同一校名・同一住所・同一電話番号のレコードは1校へ統合し、`course`フィールドへ
全日制／定時制／通信制を保持する。

### 2-2. 私立学校名簿（4ファイル、.xlsx）

いずれも1シート・1ヘッダー行というシンプルな構造。埼玉県版より整った形式。

| ファイル | シート名 | 列構成 |
| :--- | :--- | :--- |
| r8youchien_shiritsu.xlsx | 私立幼稚園 | 番号,学校名,学校設置者,郵便番号,所在地,電話番号,設置認可年月日,学則定員 |
| r8syougaku_shiritsu.xlsx | 私立小学校 | 番号,学校名,学校設置者,郵便番号,所在地,電話番号,設置認可年月日,男女区分,学則定員 |
| r8chugaku_shiritsu.xlsx | 私立中学校・中等教育学校（前期） ※シート名末尾に半角スペース | 同上（男女区分あり） |
| r8koukou_shiritsu.xlsx | 私立高等学校・中等教育学校（後期） | 番号,学校名,学校設置者,郵便番号,所在地,電話番号,設置認可年月日,**課程**,男女区分 |

- 所在地列も都道府県名なし（例: "市川市菅野3-23-1"）。同様に「千葉県」を付与する。
- `koukou`の「課程」列は `"全日制 通信制"` のようにスペース区切りで複数値が入る行がある
  （例: 敬愛大学八日市場高校）。単純な1対1マッピングにできないため、分割してcourse配列で
  保持するか、埼玉県版の1レコード統合方針に合わせて確認する。
- `設置認可年月日`はファイルによってExcelシリアル値（数値）とdatetime型が混在している
  （例: syougaku=数値、chugaku=datetime）。変換スクリプトで両対応が必要。
- `chugaku`のシート名に末尾スペースがあるため、シート名取得時に`.strip()`必須。
- `年月日`列は初期版スキーマの必須項目ではないため保持は任意（`common-data-schema.md`の
  拡張フィールドに追加するか検討）。

### 2-3. 補正資料（`r8-gakkouichiran-2_henkou_ichiran.xls`）

新設・統合・廃止・名称変更が列挙された1シートのExcel（35KB、行数少）。想定される反映手順:

1. 基礎データ（5-1-r7、基準日2025-05-01）を読み込む。
2. 補正資料（更新日2026-04-24）の各行を種別（新設／統合による廃止／名称変更／移転）に分類する。
3. 「名称変更」は該当校のレコードの学校名を置換する（例: 富津市立大貫小学校→富津市立大佐和小学校）。
4. 「廃止（統合）」は該当校のレコードを削除し、統合先が既に基礎データに含まれているか確認する。
5. 「新設」は基礎データに存在しない場合、住所・郵便番号・電話番号を別途1次資料で確認できるまで
   `pending`扱いとし、確認できない項目は空欄で保持する（推測補完しない原則）。
6. 反映結果を`docs/school-database/chiba/correction-log.md`のような形で記録し、
   どの変更をいつ・どの根拠で反映したか追跡できるようにする。

> [!NOTE]
> 新設校（例: 八千代市立みどりが丘第二小学校）の住所・電話番号が基礎データにもgakkou-ichiran
> にも含まれない場合、市区町村教育委員会の公式ページ等、追加の一次資料確認が必要になる。
> これは埼玉県版にはなかった追加ステップ。

## 3. 表示順（地区・学校種）の実装方針

### 3-1. 地区表示順

指定順:

```
千葉市各区 → 市部 → 印旛郡 → 香取郡 → 山武郡 → 長生郡 → 夷隅郡 → 安房郡
```

原本の「地区」列（葛南・東葛飾・印旛・香取・海匝・山武・長生・夷隅・安房・君津などの
教育事務所管轄区分）はこの並び順と直接一致しない。したがって：

- 委員会名（市町村名）→ 上記8区分への変換テーブルを別途作成する
  （東京都版の`MUNICIPALITY_ORDER`、埼玉県版の同等配列と同じ設計パターン）。
- 千葉市は行政区（中央区・花見川区・稲毛区・若葉区・緑区・美浜区）ごとの表示が必要か、
  「千葉市」1区分でまとめるかを実装前に確認する（ユーザー指定は「千葉市各区」なので、
  区ごとの表示が前提と解釈する）。
- 郡部は所在の郡（印旛郡・香取郡・山武郡・長生郡・夷隅郡・安房郡）に応じて分類する。
  住所文字列から郡名を判定するか、委員会名（町村名）から郡を引く変換テーブルが必要。

### 3-2. 学校種表示順

指定順（ユーザー指定、既存版と同じ）:

```
幼稚園 → 小学校 → 中学校 → 義務教育学校 → 高等学校 → 中等教育学校 → 特別支援学校
```

幼保連携型認定こども園の表示位置は指定順に含まれていない。`school_type`の値として
どこに挿入するか（幼稚園の直後、または別枠）は実装前にユーザー確認が必要。

## 4. 変換スクリプトの設計案

`tools/school-database/convert_saitama_workbooks.py` と共通のユーティリティ
（郵便番号ゼロ埋め、住所正規化、電話番号正規化、`validate_school_data.py`との連携）を再利用し、
`tools/school-database/convert_chiba_workbooks.py`（新規、未作成）として以下の処理を想定する。

1. `chiba_sources.json` を読み込み、`data-source/chiba/2025/` から各ファイルを開く。
2. 公立ファイルは1ブックから学校種ごとにシートを分けて処理する
   （埼玉県版は複数ブックを1school_typeずつ処理する設計だったため、ここが最大の実装差分）。
3. 高等学校は3シート（全日制・定時制・通信制）を学校名＋所在地＋電話番号キーで突合し、1校へ統合。
4. 私立4ファイルはシンプルな単一ヘッダーのため、共通パーサーで処理可能。
5. `r8-gakkouichiran-2` の補正を適用する（第2-3節の手順）。
6. 地区・学校種の表示順テーブルを適用してソートする。
7. 出力を`data/school-database/chiba.json`へ書き出す（**今回はここまで実行しない**）。

## 5. 検証観点（埼玉県版を継承）

- 見出し行の自動検出（千葉県は埼玉県よりマージセル構成が複雑なため要個別調整）
- 学校名・住所・郵便番号・電話番号が正しい列から取得されているか
- 高等学校の全日制・定時制・通信制の統合／分離判断
- 幼保連携型認定こども園の扱い（school_typeの値、表示順の位置）
- 私立幼稚園・小学校・中学校・高等学校の件数が県公式ページの件数と一致するか
  （現時点で件数の一次記載は未確認。ページには件数の明記が薄く、実際の行数から確定する）
- 住所に「千葉県」が二重付与されていないか
- 郵便番号・電話番号がExcelの数値化で先頭ゼロを失っていないか
- 令和7年基礎データと令和8年変更一覧の突合で反映漏れがないか
- 東京都版・埼玉県版の回帰確認が完了しているか

## 6. 公開禁止条件（埼玉県版を継承・追加）

次のいずれかに該当する場合は `prefectures.json` へ千葉県を追加しない。

- 必須校種の原本が不足
- 変換エラーが残る
- 県公式件数との不一致理由が未確認
- 抽出結果の原本照合が未完了
- 東京都版・埼玉県版の回帰確認が未完了
- **新設・統合・廃止・名称変更の反映が令和8年4月24日時点の変更一覧まで未完了**
- **幼保連携型認定こども園・地区表示順の扱いについてユーザー確認が未完了**

## 7. 次アクション（ユーザー確認待ち）

1. 幼保連携型認定こども園の`school_type`表示位置の確認
2. 千葉市の地区表示を「区ごと」にするか「千葉市」1区分にするかの確認
3. 私立高等学校の「課程」複数値（例: 全日制 通信制）の扱い方針の確認
4. 私立中等教育学校（前期・後期）を1校として統合するか、別レコードにするかの確認
5. 上記確認後、`convert_chiba_workbooks.py` の実装に着手する
