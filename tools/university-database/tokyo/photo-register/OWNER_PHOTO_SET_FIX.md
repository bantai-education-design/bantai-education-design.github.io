# 本人撮影写真登録 — 写真セット確定ルール

## 不具合

旧エンジンは「1写真=1大学」を前提にしていたため、本人登録UIで同じ大学へ複数写真を入れると重複扱いになり、登録用ZIPを生成できなかった。

また、既存写真を「一覧から削除」しても、その削除状態は画面上だけで、公開用 `user-photo-overrides.json` の再生成に使われていなかった。そのため削除した写真がサブ写真として残る可能性があった。

## 修正後の原則

- 本人モードでは **1大学=1写真セット** として扱う。
- 1大学につき最大9枚。
- メイン写真は1枚、残り最大8枚は `gallery` に保存する。
- 登録時は旧 `gallery` を継ぎ足さず、**現在残している本人写真 + 今回追加した写真だけから写真セットを再構成する**。
- 「一覧から削除」した既存本人写真は新しいレコードへ引き継がない。
- 本人写真をすべて削除し新規写真もない場合は、その大学の owner override レコード自体を削除し、公開側は通常の画像台帳へ戻る。
- 新規写真は補正後720×405 JPEGを別ファイル名で保存し、元画像も監査用ZIPへ含める。
- 生成AI再描画、景観要素の追加削除、背景置換は行わない。
- ブラウザからGitHub mainへ直接書き込まない。ZIPを確認後、CI・PR経由で正式反映する。

## 回帰テスト

亜細亜大学の既存本人写真を削除し、新規2枚を追加、2枚目をメインに指定して登録用ZIPを生成するブラウザテストを実施する。生成JSONでは旧写真URLがmain/galleryのどちらにも存在しないことを必須条件とする。
